**Peter Yang（创作者 / 产品人）**

1) 中文总结：Peter 总结 Linear 的 Nanyu 与 Delia Shum 关于"端到端搭建生产级 agent"的 5 条经验：① 先映射真实工作流——工作从哪开始、上下文存在哪、什么动作算完成、"完成"怎么定义、人在哪审阅（比如工作从 Slack 起，就让 Slack 当入口，而不是逼用户用独立聊天机器人）；② 给 agent 找上下文的工具，而不是把上下文塞进 prompt（"尽量少给指令，给它加载上下文的工具"）；③ 先做一个高频任务，再根据真实使用扩展（Linear 第一个生产工作流是把销售记录和 Slack 讨论变成 issue）；④ 先用最强模型直到跑通，有了清晰成功标准和 eval 后再测小模型做成本优化；⑤ 把每个真实失败变成一条 eval 或一个产品任务（行为差→加进 eval；缺工具→报 gap 让系统补）。

2) 中文全文翻译："我从 Linear 的 Nanyu 和 Delia Shum 那里学到的、关于如何端到端搭建一个优秀的生产级 agent 的 5 条最大收获：1. 第一步是梳理真实的工作流。搞清楚工作从哪里开始、哪些系统里装着上下文、什么动作算把活干完、'完成'意味着什么、以及人需要在哪里审阅。比如如果工作是从 Slack 开始的，那就让 Slack 成为入口，而不是逼用户去用一个单独的聊天机器人。2. 给 agent 找上下文的工具，而不是把上下文硬塞进 prompt。Jacob 说：'给它尽可能少的指令，给它加载上下文的工具，别给它上下文。'先从小处着手，再让 agent 只拉取当前任务需要的指令和数据。3. 从一个高频任务开始，再根据真实使用扩展。Linear 的第一个生产工作流是把销售记录和 Slack 讨论变成 issue。团队悄悄上线，观察人们怎么用，再基于真实用户行为去构建下一个工作流，而不是先写一份涵盖所有可能用例的宏大 spec。4. 先用最强的模型，直到工作流跑通。Jacob：'我们会把最大的模型砸上去，直到确认它跑得够好。'一旦你有了清晰的成标准和 eval，再在窄任务上测试更小的模型。成本优化应该在质量基线之后。5. 把每一个真实失败，要么变成一条 eval，要么变成一个产品任务。Linear 从真实使用里建了两条反馈回路：如果 agent 工具有但行为糟糕，团队就把这个具体案例加进 eval；如果 agent 缺需要的工具，它就上报这个缺口，系统把它加进已有的 issue 让团队排查。📌 看完整 episode 获取完整 walkthrough：https://t.co/wmw8vvjvv0"

3) 推荐理由：这是目前最接地气的"如何把 agent 真正用在生产"的方法论之一，Linear 的一线经验可直接复用，做产品和自动化的都该看。

**Madhu Guru（消费级 AI 产品负责人）**

1) 中文总结：Madhu 在思考 AI + 消费产品的核心难题：如何建立"某人为什么这么做"的理论，而不只是"他做了什么"的历史。消费产品混合了显式信号（搜索 / 对话）与隐式信号（观看、跳过、停留、回看），理解这些信号真正意味着什么，需要推理上下文——用户生活里正在发生什么、世界在发生什么、兴趣如何随时间演变；而面向十亿级用户近实时地做这件事，是另一重挑战。

2) 中文全文翻译："我最近深深陷在 AI 和消费体验交界处的这个兔子洞里：你如何去建立一套'某人为什么做了某事'的理论，而不只是'他做了什么'的历史？消费产品混合了来自搜索 / 对话的显式信号，以及来自你看了什么、跳过什么、停留什么、回看了什么的隐式信号。要理解这些信号到底意味着什么，需要对上下文进行推理——这个人生活里在发生什么，世界上在发生什么，以及他的兴趣是如何随时间演变的。而对十亿用户的消费体验做到近乎实时，又是完全不同的一重挑战。"

3) 推荐理由：从"记录行为"升级到"推理意图"是消费 AI 的下一关，对做推荐、陪伴、个性化的人都很有启发。

**Aaron Levie（Box CEO）**

1) 中文总结：Levie 连发两条谈开源权重(open weights)的意义。他说三个月前没人会相信一家美国公司会放出前沿级能力的开源权重模型，现在这打开了此前不可行的场景——本地 / 私有基础设施部署（受监管领域）、针对垂直场景（法律、医疗）后训练、以及模型被下架时的主权保障；对"应用层"尤其利好，可以按任务路由不同模型家族。他还点名 Meta 的 Muse Spark 1.2 开源权重是"美国对开源权重竞赛的关键回应"，会持续压低智能成本、让企业按需运行与后训练，给那些此前被关在 OSS 门外的人一个现实选项。

2) 中文全文翻译：
- "如果你三个月前告诉别人，一家美国公司发布的、具备前沿级能力的模型会以开源权重的形式提供，他们不会信。这非常重要，因为它开启了之前不可行的一系列 AI 采用场景。模型可以部署在本地或云端的私有基础设施上，这意味着高度监管领域的使用场景能被打开。你现在还可以在法律、医疗等需要额外性能的垂直用例上，对前沿级模型做后训练。你也获得了主权保障——万一某些模型从市场上下架，用户部署关键任务时更有信心。这一切对'应用 AI 层'都是好消息，因为你可以根据手头任务把工作路由到不同的模型家族。考虑到现在的选择，正是做 harness 层的好时机。闭源前沿模型仍会被大量使用——既因为简单，也因为你往往需要对难题混合不同能力层级——但把开源权重加进来，有助于摊薄成本、提供更多灵活性。全方位的好消息。"
- "Meta 以开源权重发布 Muse Spark 1.2 是件*非常*大事。美国现在终于有了自己对开源权重 AI 竞赛的回应。这会持续压低智能的成本，让企业按自己的想法运行模型，也能针对特定用例后训练自己的模型以获得更好的领域性能提升，并给那些此前被 OSS 模型拒之门外的人一个现实的选项。这对 AI——甚至对闭源前沿模型——整体都是净正向的，因为它有助于进一步推动 AI 的扩散。AI 竞赛里的一个重要时刻。"

3) 推荐理由：open weights 是今年最关键的供给侧变化之一，关乎成本、主权与垂直落地，做 AI 产品的都应持续跟踪。

**开场与 Netic 在做什么（00:05–02:47）**

**为什么做服务层，而不是 roll-up（06:54–10:38）**
Melisa：三个原因。一是我想在世界上构建的东西、技能与规模。我在 Scale 待了约四年，从政府到大型企业搭建了大量真实世界业务。二是个人技能——很多 roll-up 里最重要的是 M&A 本身，而我不是 M&A 的人，我是 builder、工程师、产品人，那不匹配我的技能。三是产品规模：很多成功的 roll-up，最终你做出的产品只服务于你刚买下的那几家公司，没法应用到别家；而我想的是，如何让*每一家*真实世界企业都能跑在 Netic 上——如果它们不必被限制，只需专注自己最擅长的"人力"和"服务质量差异化"，剩下的交给 Netic 来运营。

**和大实验室的差异化 / 最后一公里（13:08–15:34）**
Melisa：十年前同样的问题是"Google 能做这个吗"，后来变成"实验室能做这个吗"。有些核心能力他们能做，但有些他们根本没在投入。对 Netic 来说，我不把它们视为竞争风险，反而它们是我们的好伙伴。要服务这些行业和企业，有两件事很重要：一是聚焦——OpenAI 产品做得快但也死得快，企业（尤其这些行业的企业）并不想要那么快；二是"最后一公里"——面对全国数百万需求完全不同、口音不同、想被触达的方式不同、还要被再次触达变成回头客的用户，有大量工作不是来自模型，而是来自你必须在模型之上构建的 harness、编排和软件产品。所以我们这种公司必须在三层都做好。

**创始人心态与 agency 招聘（16:06–22:25）**
Melisa：我发现现在很多创始人太担心实验室在做什么，因为他们想的是"我能不能尽快退出"。但做创始人是一件要投入数十年、奉献整个生命的事，不该轻率。我们特别避开"追逐闪亮物体"的人。关于筛选 agency（主动性），我不看某一次经历，而是看一个人只要活着、有意识，是否持续展现主动性并坚持下去——"你启动了什么、做了别人不做的独特之事，然后你坚持下来了吗？"我常问的一个问题是："你这辈子做过最难的事是什么？"有人给过很创意的回答：一个人说他生活很简单，极度在乎工作、有一套疯狂的健康作息，最难的事是"十五年如一日，每天这个钟点起床、每几小时做这些事、对同事负责，且不厌烦、不想别的，把自己交付给在乎的事"。
