### Thariq（Claude Code @Anthropic，前 YC W20）
1) 中文总结：Thariq 连发三条关于 agent 工具设计的思考，核心意思是「别再用一层间接封装去骗模型，直接给它你想要形状的工具」：比如存数据，你真正想要的也许不是一个文件系统，而是一个指向数据库的 API。他认为 Claude Managed Agents（CMA）在 sandbox 上拿捏得很好——sandbox 是可选的，可以独立于 agent loop 之外单独拉起；他还把自己一个偏 bash 调用的老项目迁到 CMA，跑得很顺。结论上，他修正了自己去年的看法：如果目标只是稳定的工具调用，bash 已经不是「全部所需」，但 sandbox + bash 在「代码生成并执行」这类活上依然好用。
2) 中文全文翻译：
   - 推文：我觉得 Claude Managed Agents 在这里找到了合适的平衡，sandbox 是可选的，而且可以独立于 agent loop 的其余部分单独拉起来。我最近把一个偏 bash 工具调用的老项目移植到了 CMA，效果很好。
   - 推文：我越来越觉得，你可以直接给 Claude 你想要的那种形状的工具，而不是用一层间接封装去骗它。比如存数据，你真正想要的是一个文件系统，还是一个指向数据库的 API？这对我来说又是相比去年的一次更新。

3) 推荐理由：这是 Anthropic 一线 engineer 对「agent 该怎么接工具、要不要 sandbox」最实在的经验贴，和你正在做的多步 agent 产品高度相关，能少踩很多坑。
